# 3-Match Puzzle Map Tool

제작: [sungmin2ee](https://github.com/sungmin2ee)

Cave 하나를 퍼즐 레벨 하나로 편집하는 브라우저 기반 맵툴입니다.

[▶ 맵툴 실행하기](https://sungmin2ee.github.io/windy-cave-map-tool-public/)

[▶ DDUNG 퍼즐 플레이](https://sungmin2ee.github.io/windy-cave-map-tool-public/play.html)

퍼즐은 처음에 1번에서 시작합니다. 클리어 기록과 마지막으로 연 레벨은 같은 브라우저에 저장되며, 레벨 선택에서 다시 플레이할 수 있습니다. 현재 1~410번을 제공합니다. 클리어 시 남은 이동이 전체의 25% 이상이면 별 3개, 10% 이상이면 별 2개, 그 외에는 별 1개를 받습니다.

## 사용법

맵툴 상단의 **사용법**에서도 아래 내용을 볼 수 있습니다.

### 시작하기

- 기존 맵은 상단의 **JSON 가져오기**로 엽니다. 미리보기에서 레벨 수, 맵 크기, 특수 피스 종류, 읽지 못한 값을 확인한 뒤 **가져오기**를 누르세요. 취소하면 편집 중이던 프로젝트로 돌아갑니다.
- 읽지 못한 타일 목록에는 레벨, 행·열, 총 칸 수가 표시됩니다. **목록 복사**로 가져오기 문제를 공유할 수 있습니다. 외부 JSON은 지원하는 구조와 타일 매핑이 필요합니다.
- 빈 맵은 **새 프로젝트**에서 시작합니다. 왼쪽 **Caves**에서 레벨을 추가하거나 번호·이름으로 찾습니다. **다른 번호로 저장**을 누르면 번호를 직접 지정할 수 있고, 이미 있는 번호는 덮어쓰기 확인이 뜹니다.

### 보드 편집

- 왼쪽에서 맵 크기, 중력, 클리어 목표와 **Moves**를 설정합니다. 별 점수, 수동 난이도, 오브젝트 생성 방식은 **레벨별 설정**에서 입력하고 **레벨 설정 적용**을 누릅니다.
- 오른쪽에서 **Terrain / Block / Gimmick / Item** 레이어를 선택한 뒤 **오브젝트 만들기**로 등록하거나, 가져온 오브젝트를 선택합니다. **브러시**로 클릭·드래그해 배치하고 **채우기**, **지우개**, **실행 취소**로 편집합니다.
- 셀에 마우스를 올리면 속성을 볼 수 있습니다. **칸 속성**으로 초기 특수 피스의 색·종류를 편집하거나 해제할 수 있습니다. **칸 비활성화**는 해당 칸을 보드에서 제외하며, 다시 누르면 빈 칸으로 복원합니다.
- **Gimmick** 탭에는 새 프로젝트와 가져온 프로젝트 모두에서 **Spawner**가 기본으로 표시됩니다. 보드에 배치한 스포너는 **지우개**로 제거할 수 있습니다.
- 팔레트의 **사용처 보기**로 오브젝트가 쓰인 레벨과 위치를 확인할 수 있습니다. 사용 중인 종류를 삭제하려 하면 해당 사용처를 확인할 수 있습니다.

### 랜덤 생성

- 왼쪽 레벨 설정의 **랜덤 배치**에 시드와 밀도를 입력하고 **랜덤 채우기 · 시드로 블록 배치**를 누릅니다. 오른쪽 **사용 색상**에서 사용할 블록을 지정하세요.
- 같은 영역의 **보드 모양 후보**에서 모양을 골라 적용할 수 있습니다. **구역 아이템 랜덤 배치**는 행·열 범위, 아이템 종류, 개수를 받아 범위 안의 배치 가능한 빈 칸에 배치합니다. 먼저 오른쪽 **Item** 탭에 종류를 등록하세요.

- 왼쪽 **랜덤 배치 → 난이도로 보드 생성**에서 목표 난이도 `1~100`을 입력하고 **후보 생성**을 누릅니다. **사용 색상**에 생성 가중치가 0보다 큰 블록이 두 종류 이상 필요합니다. **Terrain** 탭에는 매치로 제거할 수 있는 지형을 등록하고 반응 규칙을 설정하세요.
- 생성된 보드의 클리어 목표는 **Terrain 파괴**입니다. 후보당 6회 자동 플레이를 돌려 한 번 이상 클리어한 보드 중 목표 난이도에 가까운 후보를 최대 3개 보여줍니다. 보드, 목표 수량, 제한 Moves, 추정 난이도와 클리어율을 확인하고 **이 후보 적용**을 누르세요.
- **기존 오브젝트 배치 유지**는 기본으로 켜져 있습니다. 기존 배치를 바탕으로 생성하려면 체크하고, 새로 배치하려면 체크를 해제하세요. 두 경우 모두 보드 크기와 비활성 칸을 유지합니다.
- 자동 생성 시 스포너는 중력 반대쪽 가장자리에 배치됩니다. 중력이 아래면 위쪽, 위면 아래쪽, 왼쪽이면 오른쪽, 오른쪽이면 왼쪽입니다. 비활성 칸, 막힌 지형, 다른 기믹이 있는 칸은 건너뜁니다. **기존 오브젝트 배치 유지**를 켜도 생성 후보의 스포너 위치는 이 규칙에 맞춰 조정됩니다.

### 플레이와 검증

- **블록 흐름 → 원작 방식 · 직선 우선**은 직선 낙하를 먼저 배정한 뒤 남은 빈칸의 위쪽·좌우 후보를 찾습니다. 이동 중이거나 다른 칸으로 배정된 블록은 가져오지 않습니다. 왼쪽 일반 피스가 우선이며 왼쪽이 특수 피스이면 가능한 오른쪽 후보를 먼저 사용합니다. 벽 아래에서 새 블록을 임의 생성하지 않고 생성 소스에서 공급합니다. 기존 좌우 우선·교대·랜덤 설정은 이 방식으로 읽으며, **옆으로 흐르지 않음**은 유지됩니다. 순차 Playtest와 실시간 플레이가 같은 우회 계획을 사용합니다.
- 벽 아래 우회 확인용 맵: `play.html?map=tests/fixtures/royal-flow.json&level=1`. 아래쪽 줄 폭탄을 누르면 벽 아래 빈칸으로 블록이 우회합니다. 원작의 고유 장애물별 예외와 모든 애니메이션 타이밍까지 동일하게 구현한 것은 아닙니다.
- **프로젝트 메뉴 → 프로젝트 설정 → 블록이 사라지는 중에도 교환 허용**을 켜면 편집기 Playtest와 `play.html`이 같은 실시간 실행부(`live-game.js`)를 사용합니다. 설정은 기존 JSON의 `swapDuringEffects`로 저장됩니다.
- 이 모드에서는 현재 멈춘 블록으로 즉시 교환을 판정합니다. 떨어지거나 교환 중인 피스와 진입 예정 칸은 잠그며, 실제 빈칸을 향한 유효 매치도 지원합니다. 특수 피스 탭은 별도 처리해 전체 리필 완료를 기다리지 않습니다. 향후 연쇄 결과로 현재 입력을 미리 차단하지 않습니다.
- 피스 ID, 이동 상태, 칸 예약을 유지하면서 직선·대각선·포털 낙하와 소스 리필을 단계별로 갱신합니다. 종료·이동 소진·점수 클리어는 진행 중인 효과와 연쇄가 끝나면 판정합니다. 옵션을 끄면 기존 순차 실행을 사용합니다.
- 검증: `node --test tests/live-game.test.mjs`. 로컬 서버에서 `play.html?map=tests/fixtures/live-board.json&level=1`은 중첩 입력, `play.html?map=tests/fixtures/ddung-level-7.json&level=7`은 원본 7레벨의 벌 연출을 확인할 수 있습니다. 원작 APK를 실행해 모든 타이밍과 예외를 동일하게 검증한 것은 아닙니다.

- **Playtest**는 블록 교환과 특수 피스 발동을 자동으로 진행합니다. 특수 피스를 클릭하면 바로 발동합니다. 일시정지 중에는 인접한 일반 블록 두 개를 클릭해 직접 교환할 수 있습니다. 발동에는 이동 1회를 사용합니다. 클리어 기록은 **이 기록을 난이도에 사용**으로 반영할 수 있습니다.
- **매치로 특수 피스 생성**을 켜면 가로 4매치에서 세로 줄 폭탄, 세로 4매치에서 가로 줄 폭탄이 생깁니다. 5매치는 같은 색 제거 피스, T/L자 매치는 주변 3×3 폭탄, 2×2 매치는 목표 칸으로 날아가는 벌을 만듭니다. DDUNG에서 가져온 레벨은 이 설정을 켜서 사용할 수 있습니다.
- 오른쪽 오브젝트 패널의 **특수 타입 관리**에서 현재 Cave의 특수 타입 이름과 발동 효과를 설정합니다. 효과는 해당 Cave에서 같은 타입을 사용하는 모든 피스에 적용됩니다. **칸 속성**에서 블록 색과 등록된 특수 타입을 선택해 배치합니다.
- **직접 작성한 스크립트**를 선택하면 여러 효과를 조합할 수 있습니다. 예를 들어 `[{"op":"row"},{"op":"offsets","cells":[[-1,-1],[1,1]]}]`는 피스의 가로 한 줄과 대각선 두 칸을 터뜨립니다. Playtest와 자동 플레이에서 같은 효과가 적용됩니다. 스크립트는 지원 명령을 담은 JSON 배열입니다.
- **검증**은 현재 Cave를, **범위 검증**은 지정한 번호 범위를 자동으로 검사합니다. 자동 플레이의 클리어율과 Moves는 레벨 밸런스를 비교하는 참고 지표입니다.
- **Failure Bonus 사용**은 Cave의 설정값으로 저장됩니다. 현재 Playtest와 자동 검증에서는 이 값을 사용하지 않습니다. DDUNG 원본 JSON에는 해당 항목이 없습니다.

### 저장과 JSON 내보내기

- **저장**은 현재 브라우저에 작업을 저장합니다. 백업하거나 다른 기기에서 이어서 작업하려면 **전체 레벨 JSON으로 내보내기**를 사용하세요. 이 파일에는 레벨과 편집용 프로젝트 데이터가 함께 들어갑니다.
- **현재 레벨 JSON으로 내보내기**는 지원하는 원본 형식으로 현재 Cave 한 개를 내보냅니다. DDUNG 형식에서는 이동 횟수, 별 점수, 수동 난이도, 생성 방식의 변경을 지원합니다. 보드나 목표를 바꾼 작업은 전체 레벨 JSON으로 보관하세요. DDUNG 게임의 암호화된 MapInfo.txt는 별도 변환이 필요합니다.

### 콘텐츠 버전과 패치

- 기준 상태를 **전체 레벨 JSON으로 내보내기**로 보관합니다. 편집 후 상단 **CONTENT VERSION**을 직접 입력하거나 `− / +`로 바꿉니다. 예를 들어 기준이 `58`이면 수정본은 `59`로 지정합니다.
- **패치 내보내기**에서 기준 전체 JSON을 선택합니다. 미리보기에서 추가·수정·삭제된 Cave와 수정된 칸의 이전 값과 새 값, 목표 및 Moves의 변경을 확인합니다. 검증 오류가 난 Cave는 미리보기에서 편집 화면으로 이동할 수 있습니다.
- **패치 다운로드**를 누르면 변경분 JSON이 저장됩니다. **같은 기준으로 패치 미리보기**로 다시 열면 마지막으로 보던 Cave 상세나 검증 오류에서 편집하러 이동한 Cave가 열립니다.
- 맵툴에서 패치 JSON을 가져오려면 현재 콘텐츠 버전이 패치의 `baseContentVersion`과 정확히 일치해야 합니다. 적용 후에는 `contentVersion`으로 갱신됩니다. `CLIENT`는 맵툴 코드 버전, `SCHEMA`는 JSON 구조 버전입니다.

## 플레이 화면 이미지 교체

테마 폴더에 이미지와 JSON을 추가한 뒤, 같은 GitHub Pages에서 `play.html?theme=themes/ocon/theme.json` 링크를 열면 적용됩니다. 이미지 경로는 테마 JSON 파일이 있는 폴더를 기준으로 해석합니다. [동작 예시](https://sungmin2ee.github.io/windy-cave-map-tool-public/play.html?theme=themes/example.json)에서는 기존 이미지로 파랑과 초록 블록의 표시를 바꿉니다.

| 설정 | 키와 값 |
| --- | --- |
| `background` | 배경 이미지 경로 |
| `block`, `terrain`, `gimmick`, `item` | 에디터의 오브젝트 ID와 이미지 경로. 예를 들어 `"block": { "blue": "./blue.webp" }` |
| `specials` | 피스 타입 ID 또는 효과 ID와 이미지 경로. 예를 들어 `"specials": { "row": "./line.webp", "fish": "./bee.webp" }` |
| `goals` | 목표 오브젝트 ID와 아이콘 경로. 생략하면 해당 레이어의 테마 이미지 또는 기본 아이콘을 사용합니다. |

필요한 항목만 지정하면 됩니다. 블록 ID와 맵의 설정은 그대로이며, 테마 링크에서도 같은 브라우저의 진행 기록을 사용합니다.

기본 블록 제거 효과는 작은 파티클과 짧은 팝 사운드입니다. 같은 테마 JSON의 `effects.blockBurst`에서 교체할 수 있습니다. `particle`은 투명 배경 이미지, `sound`는 브라우저가 재생할 수 있는 오디오 파일, `volume`은 0~1입니다. 필요한 값만 넣으면 됩니다.

```json
{
  "effects": {
    "blockBurst": {
      "particle": "./spark.webp",
      "sound": "./pop.mp3",
      "volume": 0.3
    }
  }
}
```

## 다른 게임에서 레벨 실행하기

맵툴에서 **전체 레벨 JSON으로 내보내기**를 선택해 파일을 호스팅합니다. 같은 GitHub Pages에 올리거나, 다른 호스트에서 퍼즐 사이트의 CORS 요청을 허용하면 됩니다. 아래 예제는 iframe에 JSON의 7번 Cave를 바로 엽니다. `level`에는 Cave 번호 또는 ID를 넣을 수 있고, 생략하면 JSON에 저장된 현재 Cave를 엽니다. `theme`도 기존 방식으로 함께 지정할 수 있습니다.

```html
<iframe id="puzzle" title="퍼즐 게임"></iframe>
<script>
  const frame = document.getElementById("puzzle");
  const url = new URL("https://sungmin2ee.github.io/windy-cave-map-tool-public/play.html");
  url.searchParams.set("map", "./maps/ocon.json");
  url.searchParams.set("level", "7");
  url.searchParams.set("resultOrigin", location.origin);
  const requestId = crypto.randomUUID();
  url.searchParams.set("requestId", requestId);

  window.addEventListener("message", (event) => {
    if (event.origin !== url.origin || event.source !== frame.contentWindow) return;
    const result = event.data;
    if (result?.type !== "windy-cave:puzzle-result" ||
        result.version !== 1 || result.requestId !== requestId) return;
    console.log(result.levelId, result.level, result.success, result.movesUsed, result.stars);
  });
  frame.src = url.href;
</script>
```

`resultOrigin`은 결과를 받을 게임의 오리진입니다. 호출한 iframe의 부모 창이나 팝업을 연 창에 한 판당 한 번 전송합니다. 실패하면 `success: false`, `stars: 0`입니다. 다시 시작해 끝낸 판은 별도의 결과를 보냅니다. 지정 레벨은 기본 캠페인의 진행 기록을 읽거나 저장하지 않습니다. 메시지는 브라우저에서 발생한 게임 결과이므로, 서버에서 지급하는 보상의 증빙이 필요하다면 호출 게임이 별도로 검증해야 합니다.

### 다른 게임 화면 안에서 실행

맵툴 상단의 **현재 레벨을 데모에서 열기**를 누르면 편집 중인 레벨의 보드, 목표, 점수 설정을 새 데모 탭에서 즉시 테스트할 수 있습니다. 편집 화면에서 설정을 바꾼 뒤에는 맵툴에서 버튼을 다시 눌러 최신 상태를 엽니다.

같은 HTTP 서버에서 [연동 데모](./host-demo.html)를 열면 맵 JSON, 레벨, 테마, 규칙을 지정해 한 판을 실행할 수 있습니다. 기존 호출 주소에 `embed=1`을 추가하고, 매번 새로운 `requestId`와 호출 게임의 `resultOrigin`을 전달합니다. iframe에는 `allow="autoplay"`를 지정합니다. 플레이어가 퍼즐을 처음 조작할 때 오디오가 활성화됩니다.

| 메시지 (`version: 1`) | 동작 |
| --- | --- |
| `windy-cave:puzzle-ready` | 레벨 로드 완료 |
| `windy-cave:puzzle-result` | `outcome`이 `won`, `lost`, `cancelled` 중 하나입니다. 시작된 판에는 `levelId`, `level`, `success`, `movesUsed`, `stars`, `score`가 포함됩니다. |
| `windy-cave:puzzle-error` | 로드 실패 시 `code`와 `message`를 반환합니다. |
| `windy-cave:puzzle-cancel` | 호출 게임에서 퍼즐로 보내는 종료 요청입니다. 같은 `requestId`와 `version`을 보내면 퍼즐이 결과를 반환합니다. |

수신 시 퍼즐의 오리진, iframe 창, 현재 `requestId`를 확인하고, 첫 종료 응답을 소비한 뒤 iframe을 제거합니다. 예제는 클리어 시 별 한 개당 예제 코인 10개를 표시합니다.

`mapVersion`은 맵의 `contentVersion` 또는 `version`, `themeVersion`은 테마의 `version`과 일치해야 합니다. 연동 데모 기본값은 [웹 데모 v1](./releases/web-demo/v1/)을 가리킵니다. 이 경로에 맵 v68, 규칙 v1, 테마 v1과 테마가 참조하는 이미지 및 효과음을 함께 보관합니다. 다음 조합을 배포할 때는 새 디렉터리를 만들고 호출 게임의 URL을 새 경로로 지정합니다. 테마 버전을 지정하지 않으면 테마 로드 실패 시 기본 테마로 진행합니다. 개별 이미지나 효과음이 누락된 경우에는 해당 기본 효과를 사용합니다.

`rules`에 [규칙 JSON](./host-rules.json)을 지정할 수 있습니다. `threeStars`와 `twoStars`는 클리어 시 필요한 남은 이동 비율입니다. 점수는 목표 달성 수에 `pointsPerGoalUnit`을 곱하고, 클리어한 경우에만 남은 이동 수에 `pointsPerMoveLeft`를 곱해 더합니다. 설정하지 않으면 기존 별점 기준을 사용하며 점수는 0입니다.

맵툴의 **레벨 설정 → 클리어 방식**에서 **기존 미션** 또는 **목표 점수**를 고릅니다. 점수제에서는 목표 점수와 블록당 점수를 입력합니다. 전체 레벨 내보내기와 점수제 레벨의 현재 레벨 내보내기는 `caves` 배열의 해당 레벨에 `scoreTarget`과 `pointsPerBlock`을 저장합니다. 내보낸 파일을 호스팅하고 연동 데모의 **맵 JSON**에 주소를 입력한 뒤 **퍼즐 시작**을 누르면 레벨 설정으로 플레이합니다. 버전 확인을 쓰는 경우 데모의 **맵 버전**을 내보낸 파일의 `contentVersion`에 맞춥니다.

연동 데모에서 **500점 도전**을 누르면 [점수 도전 규칙](./releases/web-demo/v1/score-rules-v1.json)을 사용합니다. 규칙 파일에 있는 `scoreTarget`과 `pointsPerBlock`은 입력된 항목만 레벨 설정에 우선 적용합니다. 양의 정수 `scoreTarget`을 지정하면 매치와 특수 피스로 제거한 블록마다 `pointsPerBlock`(기본 100점)을 얻고, 연쇄 제거도 합산합니다. 한 턴이 끝날 때 누적 점수가 목표 이상이면 클리어합니다. 남은 이동 보너스는 클리어 후 최종 점수에 더합니다. 결과에는 `score`와 `scoreTarget`이 포함됩니다. 레벨과 규칙에 목표 점수가 없으면 기존 미션으로 진행합니다.

## 로컬 실행

저장소 루트에서 정적 HTTP 서버를 실행합니다.

```bash
python -m http.server 4173
```

브라우저에서 `http://localhost:4173`을 엽니다.
