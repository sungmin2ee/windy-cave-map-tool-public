# 2026-11-19 변경 기록 — 테마 편집부터 로얄매치 규칙 적용까지

기록 기준: 2026-11-18 11:15 KST, “일단 지금부터 하는거 나중에 노션에다 정리할거니까 알아두고있어” 요청 이후. 기록 시점의 클라이언트는 2.7.56, JSON 스키마는 5다.

## 1. 테마 편집과 재사용

- 일반 블록·특수 피스·목표 등의 이미지를 편집하는 테마 화면을 추가했다. 예시 이미지를 사용해 이미지 교체를 확인했다.
- 여러 교체 이미지를 테마 팩 JSON으로 저장하고 다른 맵에서 불러올 수 있게 했다. 불러온 팩을 현재 맵툴의 편집 보드에도 적용할 수 있다.
- 벌을 눌러 발동할 때 기본 이미지가 다시 나오던 문제를 수정했다. 편집 화면과 발동 연출에서 테마 이미지를 사용하도록 연결했다.
- 오브젝트 편집에서 지정한 이미지가 테마 편집에도 반영되게 하고, 기본 이미지로 되돌리는 동작을 정비했다.
- 불필요하다고 판단한 ‘예제 레벨로 시작’은 제거했다.

## 2. 편집 순서와 모바일 화면

- 레벨 목록·레벨 설정·보드 편집·오브젝트를 탭으로 나눴다. 가이드 따라가기는 단계에 맞는 탭과 설정 위치로 이동한다.
- 현재 순서: 레벨 선택 → 보드 크기 → 배치할 오브젝트 편집 → 보드 모양 → 클리어 목표·이동 횟수 → 난이도 후보 생성 → 자동 배치 → 플레이 미리보기.
- 보드 모양 생성과 난이도 후보 생성을 분리했다. 필요 없는 단계는 건너뛸 수 있다. 가이드를 사용하지 않아도 보드를 먼저 편집할 수 있다.
- 클리어 목표와 이동 제한을 먼저 정하고 그 조건으로 난이도 시뮬레이션을 진행하도록 순서를 바꿨다. 이동 횟수 제한은 체크박스로 켜거나 끈다.
- 랜덤 채우기·시드 배치 결과를 보드에서 바로 확인하도록 했다. 사용할 블록 종류 검사와 후보 생성 동작도 정비했다.
- 모바일의 메뉴 겹침과 화면 밖으로 나가는 배치를 수정하고, 가이드의 이전·다음·안내 닫기 배치를 정리했다.

## 3. 모든 레벨의 공용 규칙과 JSON 목표

- 지형·기믹의 행동 규칙을 프로젝트 전체 레벨에서 공유한다. 같은 오브젝트는 레벨마다 임의로 다른 행동을 하지 않도록 했다.
- 맵툴 JSON에 명시된 수량 방식과 점수제 설정을 가져오기·Playtest에 반영한다. 명시된 직접 입력 목표를 자동 수량으로 덮어쓰지 않도록 했다.
- 원본 DDUNG JSON의 일부 목표는 Unity가 실제 보드에 남은 개수를 기준으로 판정한다. 원본 1레벨은 저장된 물 수량 16과 별개로, 보드의 물 30개를 모두 제거하는 조건이다. 맵툴에서 직접 입력 16개로 저장한 레벨이나 500점 목표로 저장한 레벨과 구분한다.
- 보드 전체 제거 목표, 여러 칸을 차지하는 지형 그룹, 참나무 목표와 얼음 주머니, 색상 목표의 특수 피스 집계 등을 공용 엔진에서 보정했다. 개별 레벨·모든 기믹을 원본 Unity 실행과 전수 비교한 완료 상태는 아니다.

## 4. REA를 사용한 Royal Match 40220 분석

사용자가 제공한 `Royal+Match_40220_APKPure.xapk`를 대상으로 낙하·교환·특수 피스 탭·막힘 우회 경로를 조사했다.

- REA로 XAPK/APK 구성과 Unity IL2CPP v31 메타데이터를 확인했다.
- REA의 전체 native-link는 pointer-index 용량 제한으로 중단됐고, Windows Ghidra provider도 해당 ARM64 ELF를 지원하지 않았다. 이를 함수 본문 분석 성공으로 기록하지 않았다.
- 메타데이터와 ELF의 method pointer를 보조 스크립트로 연결한 뒤 설치된 Ghidra를 직접 실행해 관련 함수 본문을 추가 확인했다.
- Android 원작을 실행해 프레임 단위로 검증한 결과가 아니라 정적 코드 분석 결과다. 원본 바이너리·역컴파일 본문·원작 이미지와 사운드는 공개 웹 저장소에 추가하지 않았다.

| 분석 구간 | 확인한 원리 | 웹에 적용한 내용 |
| --- | --- | --- |
| 입력 잠금 | 전체 입력 잠금과 개별 칸·피스 상태를 구분 | 다른 곳의 소멸·낙하가 모든 입력을 막지 않도록 분리 |
| 일반 교환 | 정지 상태, 교환 중 여부, 진입 예정 피스를 검사 | 멈춘 피스는 즉시 교환하고, 이동 중인 피스·예약 칸은 잠금 |

## 5. 실시간 플레이와 우회 흐름 적용

- 공용 실시간 실행부 `live-game.js`를 추가했다. 편집기 Playtest와 플레이 배포판이 같은 피스 ID·이동 상태·예약 칸을 사용한다.
- 미래 연쇄 결과를 끝까지 계산한 뒤 화면만 재생하던 입력 처리를 현재 상태 기준으로 교체했다. 예약 입력 대신 현재 가능한 교환·특수 탭을 즉시 실행한다.
- 프로젝트 설정의 ‘블록이 사라지는 중에도 교환 허용’으로 켜거나 끈다. JSON에는 `swapDuringEffects`로 저장한다. 끄면 순차 실행을 사용한다.
- 우회 모드는 `royal`을 기본으로 사용한다. 직선 공급이 가능한 열을 옆 열이 가로채지 않으며, 이미 다른 빈칸에 배정된 블록은 중복 사용하지 않는다. 깊은 빈 공간으로 순간 이동하지 않고 위쪽 진입 칸부터 내려온다.
- 벽 아래에서 임의로 새 블록을 만들지 않고 생성 소스에서 공급한다. 포털·지역 중력도 같은 계획에 반영한다. 순차 Playtest에도 같은 우회 계획을 적용했다.
- 기존 좌우 우선·교대·시드 랜덤 우회 설정은 원작 방식으로 읽는다. 명시적인 ‘옆으로 흐르지 않음’은 유지한다.
- 기본 재생 속도는 1×로 조정했다. 웹의 낙하 속도를 원작의 정확한 물리 수치나 시간과 동일하다고 보장하지 않는다.

## 6. 연출·입력 버그 수정

- 벌 비행 연출이 끝나도 일반 블록 위에 남던 임시 이미지를 제거했다. 쥐·거미 임시 연출도 종료 시 정리한다.
- 마지막 목표를 향해 벌이 날아갈 때 추가 이동을 할 수 있던 문제를 수정했다. 목표 달성 즉시 새 입력을 닫고, 비행·연쇄가 끝난 뒤 결과 팝업을 연다. 다른 목표가 남아 있으면 동시 입력은 유지한다.
- 낙하 갱신마다 이미지 로드 표시를 변경으로 오인해 이미지를 재생성하던 문제를 수정했다. 같은 시각 정보는 기존 이미지 노드를 유지하며, 이미 로드된 이미지의 표시 상태를 즉시 반영한다.
- 실패한 교환에서 원래 블록과 왕복 연출이 동시에 보이던 문제를 수정했다. 지연된 복귀 이미지는 차례가 올 때만 표시하고, 연출 중인 칸의 기본 이미지는 숨긴다. 복귀 후 이미지를 복원하며 이동 횟수는 차감하지 않는다.

## 9. 추가 변경 — 기본 교환 허용과 빈칸 잠금 분리 (2.7.58)

- ‘블록이 사라지는 중에도 교환 허용’을 기본으로 켰다. 새 프로젝트와 해당 설정이 없는 JSON은 활성화하고, 체크를 끄거나 JSON에 `swapDuringEffects: false`를 저장하면 순차 실행으로 소멸·낙하 중 교환을 막는다. 명시적으로 끈 설정은 다시 불러와도 유지한다.
- 로얄매치 40220의 `IsEmptyCell`·`IsSwappableEmptyCell`·`CanSwapTo` 정적 분석을 다시 대조했다. 현재 피스와 바로 진입할 피스의 점유를 검사하는 입력 판정과 먼 최종 낙하 목표 예약을 분리했다.
- 입력·매치 판정에는 이동 중인 피스의 출발/다음 진입 칸과 제거·교환 잠금을 사용한다. 먼 최종 낙하 목표라는 이유만으로 실제 빈칸의 교환을 막지 않는다. 최종 목표 예약은 낙하 계획에 유지해 중복 배정은 방지한다.
- 브라우저에서 20 → 26으로 이동 중이며 최종 목표가 32인 상황을 재현했다. 20·26은 잠기고 빈칸 32는 교환 가능했다. 31 → 32의 유효 매치는 다른 낙하가 계속되는 중에 즉시 적용되어 남은 이동이 24 → 23이 됐다.
- 같은 상황에서 33 → 32의 무효 교환도 직접 실행했다. 원위치로 복귀하며 남은 이동 24회를 유지했고 기존 낙하는 계속됐다. 종료 후 다시 조작할 수 있었으며 브라우저 오류는 없었다.
- 자동 회귀 테스트 36개 통과. 설정 생략/true/false 및 false의 JSON 재가져오기 검사, JS 구문 검사와 `git diff --check` 통과.
- [빈칸 교환 확인용 맵](https://sungmin2ee.github.io/windy-cave-map-tool-public/play.html?map=tests/fixtures/empty-swap.json&level=1). 모서리 폭탄을 누른 뒤 아래 행의 빨간 블록을 빈칸으로 옮겨 확인한다. 원작 Android 실행과 모든 타이밍의 일치를 확인한 것은 아니다.

## 10. 추가 변경 — 클리어 후 남은 MOVE 특수 피스 보너스 (2.7.59)

- 목표 달성 후 기존 연쇄가 끝나면 남은 MOVE 1회당 가로 줄 폭탄·세로 줄 폭탄·폭탄·벌 중 하나를 랜덤으로 생성한다. 생성할 때 표시 카운터를 1씩 줄인다.
- 생성된 특수 피스와 보드에 남아 있던 특수 피스를 자동 발동한다. 개별 피스마다 착지를 기다리면 오래 걸리던 부분을 묶음 발동으로 조정했다. 자리가 부족하면 생성·발동을 나눠 진행한다.
- 보너스 중에는 보드 입력을 닫고, 발동·낙하·연쇄가 끝난 뒤 클리어 팝업과 연동 결과를 표시한다. 목표 달성 뒤 턴 종료 장애물이 실패로 바꾸지 않도록 처리했다.
- 표시 MOVE는 0까지 줄어들지만 별점·호스트 반환용 실제 사용 이동 횟수·남은 이동 보너스는 클리어 시점의 이동 기록을 유지한다. 보너스로 제거한 블록은 점수에 합산한다.
- 남은 MOVE가 0이거나 이동 제한이 없으면 이동 전환을 생략한다. 순차·실시간 미리보기에서 모두 지원하며 자동 난이도 검증에서는 보너스 연출을 생략한다.
